# 状态输出与用户正则

5.72.0 移除插件向正则队列持续写入隐藏规则的机制。5.72.2 进一步取消格式化结果中的文本删除，改为在 Markdown 渲染之后包裹隐藏容器。用户正则、后续格式化钩子和原始消息读取均保留各自的数据输入。

## 有格式化接口的宿主

当 `SillyTavern.getContext().messageFormatter` 提供 `AFTER_MARKDOWN` 时，注册一个同步显示钩子：

```text
保存的聊天原文 → 用户正则完整运行 → Markdown → 将剩余协议块放入隐藏容器 → 宿主净化 → 显示
保存的聊天原文 → 状态引擎解析 → 状态存档
```

仅将完整的 `life_state`、`state_handoff`、`story_time` 标签块包裹在带 `hidden` 与 `display:none!important` 的容器中。协议边界转为可读取的文本，避免宿主净化器丢弃未知 HTML 标签。也识别酒馆“转义标签”模式产生的 `&lt;life_state&gt;`。用户消息、系统消息、推理内容和独立预览跳过。未闭合的流式块保留到标签完整；字符串扫描避开 HTML 属性及 script、style、textarea 中的字面量。

隐藏文本仍存在于 DOM 的 `textContent` 中。`innerText` 表示可见内容，隐藏部分为空是正常的；状态解析始终读取原始消息字段，不能使用 `innerText`、格式化 HTML 或其他分支的缓存充当模型原始回复。隐藏功能不改模型输出协议。

用户正则若把状态块转换为自己的 HTML 面板，转换结果不再是协议标签，便保留给宿主正常渲染和净化。整段包裹正则能先读到完整原文。插件不改 `chat[].mes`、提示词或用户规则顺序。

同一格式化注册表只保留一个本插件回调。停用时解除激活并展开现有隐藏容器，重新启用不叠加回调。编辑或切换分支时按当前原文重新渲染，隐藏功能不保存可被误用的历史状态副本。

## 没有格式化接口的旧宿主

在宿主完成消息渲染后，观察聊天 DOM，对比聊天原文中完整协议块，只隐藏普通文本或无属性段落中精确匹配的尾部，允许宿主产生的引号、加粗和强调节点。优先识别完整标签；标签被宿主去掉时，较长的 JSON 对象／数组允许按载荷匹配。提取出的节点放入隐藏容器，文本继续保留。

带标签属性的容器、自定义 `details`、`article`、`pre` 等结构不做载荷裁切；短词、短 JSON、无法匹配或不在尾部的内容保留显示。这样避免把用户正则制作的面板内容误当成残留输出。该模式可能保留少量状态文本，不能保证每种任意转换后的文本都隐藏。停用时解除观察并恢复隐藏范围，不替换前方正文控件。

## 旧规则迁移与边界

仅迁移 ID 与转换特征匹配的旧插件隐藏规则；用户修改了匹配、替换、适用位置或深度等设置的规则保留。同名但不同 ID 的规则不动。迁移保存一次设置，不再为刷新正则列表触发假的聊天切换事件。

这里解决的是插件隐藏动作抢先破坏用户正则输入的问题。若用户正则本身删除或改写保存的原文、把协议变成无法辨认的文本，或其他扩展继续改写显示结果，插件不能自动还原丢失的信息，也不能对任意正则语义作绝对保证。

“查看返回”及复制报告显示读取来源、原文长度和完整状态块数量。当前分支原文为空时明确显示“聊天原文为空”，与格式正确后的保存错误分别报告。

浏览器回归使用模拟宿主格式化接口、实际 Showdown 与 DOMPurify，检查整段替换、自定义状态面板、原文及隐藏文本保留、流式补全、编辑重绘、启停、迁移与旧宿主 DOM。对只有状态块的一条回复，还验证消息接收事件后的自动保存、聊天重载，以及空白新分支不会误用旧数据。测试覆盖普通显示、转义标签和旧宿主三种模式。未在用户的真实正则配置或 Tauri 原生应用中逐项实测。

与 5.72.1 的对照复现中，同一条 736 字符状态回复的渲染文本由 0 恢复为 736，可见文本仍为 0；两个版本的原文均保持完整、可被核心解析。因此已确认并修正格式化结果被删空的问题，尚不能据此认定用户之前的“保存未成功”就是同一原因。
