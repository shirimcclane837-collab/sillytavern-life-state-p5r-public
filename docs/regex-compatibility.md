# 状态输出与用户正则

5.72.0 移除插件向正则队列持续写入隐藏规则的机制。旧机制会在其他显示正则之前删掉状态块，导致依赖完整输出的正则失配。现在先让宿主处理用户正则，再处理仍然可辨认的协议输出。

## 有格式化接口的宿主

当 `SillyTavern.getContext().messageFormatter` 提供 `AFTER_REGEX` 时，注册一个同步显示钩子：

```text
保存的聊天原文 → 用户正则完整运行 → 隐藏剩余协议块 → Markdown / 宿主净化 → 显示
```

仅移除完整的 `life_state`、`state_handoff`、`story_time` 标签块。用户消息、系统消息、推理内容和独立预览跳过。未闭合的流式块保留到标签完整；字符串扫描避开 HTML 属性及 script、style、textarea 中的字面量。

用户正则若把状态块转换为自己的 HTML 面板，转换结果不再是协议标签，便保留给宿主正常渲染和净化。整段包裹正则能先读到完整原文。插件不改 `chat[].mes`、提示词或用户规则顺序。

同一格式化注册表只保留一个本插件回调。停用时解除激活，重新启用不叠加回调；已渲染的显示内容随宿主下一次重绘恢复。

## 没有格式化接口的旧宿主

在宿主完成消息渲染后，观察聊天 DOM，对比聊天原文中完整协议块，只隐藏普通文本或无属性段落中精确匹配的尾部。优先识别完整标签；标签被宿主去掉时，较长的 JSON 对象／数组允许按载荷匹配。

带标签属性的容器、自定义 `details`、`article`、`pre` 等结构不做载荷裁切；短词、短 JSON、无法匹配或不在尾部的内容保留显示。这样避免把用户正则制作的面板内容误当成残留输出。该模式可能保留少量状态文本，不能保证每种任意转换后的文本都隐藏。停用时解除观察并恢复隐藏范围，不替换前方正文控件。

## 旧规则迁移与边界

仅迁移 ID 与转换特征匹配的旧插件隐藏规则；用户修改了匹配、替换、适用位置或深度等设置的规则保留。同名但不同 ID 的规则不动。迁移保存一次设置，不再为刷新正则列表触发假的聊天切换事件。

这里解决的是插件隐藏动作抢先破坏用户正则输入的问题。若用户正则本身删除或改写保存的原文、把协议变成无法辨认的文本，或其他扩展继续改写显示结果，插件不能自动还原丢失的信息，也不能对任意正则语义作绝对保证。

浏览器回归使用模拟宿主格式化接口和实际 DOMPurify，检查整段替换、自定义状态面板、原文保留、编辑重绘、启停、迁移与旧宿主 DOM。未在用户的真实正则配置或 Tauri 原生应用中逐项实测。
